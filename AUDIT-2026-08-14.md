## Findings by entry

### 1. swallowed-exceptions

**legitimate-variant (repeat)** — `substratum/verify.py:88` still catches
`Exception` (`# noqa: BLE001`) and returns the frozen four-check gate's
structural-red diagnostic. The cue matches, but this is the documented
normalization trust boundary: every parse failure must become a structural
result rather than escape the gate, and it does not substitute an empty /
not-found value.

The new `except OSError: pass` in
`substratum/formats/wii_partition.py:311` (`MaterializedPartition._remove`)
matches the empty-handler cue. Triaged as the checklist's best-effort
cleanup case: it runs from `weakref.finalize` / `close()`, and raising
would mask the original error or a shutdown path. The `except BaseException:`
sites in `wii_partition.py:359`, `chd.py`, and the 3DS enc modules still
clean up then re-raise.

### 2. hardcoded-config-values

**legitimate-variant (repeat)** — `tests/conftest.py:89` retains its literal
two-second daemon-thread join ceiling. The numeric-literal-in-an-API-call cue
matches, but the ceiling is over 80× the documented 25 ms sampler cadence and
cannot block process exit. Runtime/seedtool timeouts, batch sizes (512 raw
sectors, 256-window CTR blocks, 4-entry 3DS decrypt cache), AES block size,
ISO9660 `_VDS_SCAN_CAP = 64`, and NCCH/Wii/GD offsets are otherwise named
module constants or protocol constants. The new perf contract
`pulled <= 0x100` in `tests/test_wii_partition.py:421` is a test assertion
bound, not a silent API default.

### 3. missing-network-timeout

**no candidates** — grepped every `subprocess.run` / `urlopen` in
`substratum/` and `seedtools/`. Runtime (`chd.py`, `three_ds_ncch_enc.py`,
`three_ds_ncch_enc_seed.py`) and every seedtool call still pass a named
timeout. `urllib.request.urlopen` in `vendor_tools.py:117` still carries
`DOWNLOAD_TIMEOUT_SECONDS`. `tests/test_tooling_hardening.py:17-32` still
AST-enforces the invariant. The new `materialize()` path does not spawn
processes.

### 4. narrating-comments

**false-positive-shape (repeat)** — the new surface carries dense provenance
comments (CBC random-access property and the 0x30 IV/ciphertext gap in
`wii_partition.py:188-227`, GD-ROM hex-tens minutes in
`saturn_dc_raw.py:74-84`, disc-absolute extents in
`iso9660.py:165-174` / `_record_extent_and_size` at 50-59). These explain
non-obvious constraints (Wii cluster geometry, DC address encoding, RE4
single-sided corruption) and mirror the frozen four-check protocol banners
in `verify.py`, which the checklist permits as phase-boundary / algorithm
comments. No comment restates the line beneath it in prose.

### 5. near-identical-siblings

**false-positive-shape (repeat)** — `_from_bcd` and `_decode_minute` in
`saturn_dc_raw.py` share a nibble-split skeleton, but they are only two
siblings and differ in the load-bearing rule (strict BCD vs hex tens on the
minute high nibble). The three `_TempFileSource` wrappers (`chd.py`,
`three_ds_ncch_enc.py`, `three_ds_ncch_enc_seed.py`) remain intentionally
duplicated so each decode layer is independently dispatchable.
`MaterializedPartition` looks related but is a spool+finalize owner, not a
lazy decrypt source. Collapsing any of these would obscure format-specific
refusal/geometry rules. No three-or-more sequential blocks differing only
in an identifier.

### 6. convention-drift

**legitimate-variant (new)** — `normalize_iso9660` now takes `*, lba_base=0`
and GD-ROM composition is documented as
`normalize_iso9660(view.source, lba_base=lba_base(track))`
(`saturn_dc_raw.py:223-236`). Sibling decode layers (CHD, CSO, PS1) still
compose through the public dispatcher as `normalize(view)` /
`normalize(view.source)`. The extra-parameter cue matches, but the frozen
dispatcher (`normalize(source, *, format=None)`) cannot carry a
format-specific kwarg, and auto-detection was explicitly rejected (an
extent below the declared base must be a structural red, never a silent
retry). The format function is the documented composition path; the
dispatcher stays uniform. See also uncategorized observation 1.

Sibling normalizer naming, one-layer return shapes, sniff/normalize pairs,
path-component guards (`.`, `..`, `/`, `\`), and manifest construction
remain consistent. The prior path-component fix still holds at
`iso9660.py:88`, `gc_fst.py:62`, `wii_u8_arc.py:69`, `wii_fst.py:94`.

### 7. inconsistent-error-handling

**legitimate-variant (repeat)** — CHD / ctrtool / keyset discovery still
raises `FileNotFoundError` (or a closed `ValueError` naming the missing
env-var path) for absent operator machinery, whereas malformed media raises
`ValueError`. The sibling-wrapper cue matches, but missing operator
machinery and malformed on-media input remain genuinely distinct failure
classes. New helpers (`lba_base`, `materialize`, `_record_extent_and_size`)
raise `ValueError` for bad media, matching the public normalizer contract.

## Uncategorized observations

1. **GD-ROM composition is a footgun on the frozen dispatcher.**
   `DESIGN.md` §1 still describes caller composition as
   `normalize(view)`. A GD-ROM remap sniffs as iso9660 (CD001 at sector
   16), so `normalize(view.source)` walks with `lba_base=0` and either
   structurally reds or misreads disc-absolute extents. The correct path
   is the format-specific call documented in `lba_base()`'s docstring.
   Not a taxonomy defect — the extra kwarg cannot ride the frozen
   `normalize(source, *, format=None)` — but the advertised composition
   sentence is now incomplete for this one pairing.

2. **`_both_endian_32` is dead code.** `iso9660.py:39-44` is defined and
   never called. Before `d5f5827` it was the directory-record and root
   parser; `_record_extent_and_size` replaced those call sites and left
   the helper behind. Block-size both-endian is still checked inline
   (not via this helper). Harmless, but the module docstring (lines 8-10)
   still lists "both-endian field mismatches" as an unconditional
   structural red, which is now only true for *ambiguous* mismatches and
   for the PVD block-size field.

3. **Status docs lag the audited head.** `substratum/__init__.py` and
   `pyproject.toml` are 0.0.19; `README.md` Status and `BACKLOG.md`
   Current boundary still say 0.0.18. NORMALIZERS.md's iso9660 notes
   column both still says "refuses … BE-mismatch" and, later in the same
   cell, documents the 2026-08-14 single-sided tolerance — an internal
   contradiction. The 07-30 memo's "documentation matches the code"
   claim does not hold for these three files after the version bump and
   the RE4 rule change.

4. **RE4 retail proof is log-only.** SA2 GD composition has a
   skipif-guarded test (`test_sa2_gd_composition_is_green`). The RE4
   both-endian walk (9 files, `IOPRP.IMG` at the BE pair) is recorded in
   BACKLOG / NORMALIZERS / the session log but has no corresponding
   skipif test in `tests/test_iso9660.py` — only synthetic mutations.
   The four-check gate therefore does not re-prove the consumer-ask disc
   on a later run.

5. **Dead statement in a new test.** `tests/test_saturn_dc_raw.py:491`
   is `data[0]  # no-op; keep sector 1's minute but corrupt its low
   nibble` — a statement with no effect, leftover from editing. The
   following line does the real corruption.

6. **Key-discipline is still sound.** Wii common key and 3DS keyset still
   load from env-var paths, fail closed, and are never hashed, logged, or
   echoed. `materialize()` keeps the title key in memory only for the
   spool. No retail key bytes or decrypted retail payloads enter git.
