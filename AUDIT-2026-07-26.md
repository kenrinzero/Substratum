- **Target:** all production runtime, fixture-authoring tools, and the shipped
  conformance gate under `substratum/`, `seedtools/`, and `tests/`
- **Languages:** Python 3.13
- **Taxonomy:** `code-audit` checklist, all 24 entries in order
- **Prior audit memos:** none found

## Findings by entry

### 1. swallowed-exceptions

**legitimate-variant** — `substratum/verify.py:85` catches `Exception` and
returns a structural-red diagnostic. The cue matched (`# noqa: BLE001`), but
this is the documented trust boundary of the four-check gate: every
normalizer parse failure must become a structural result rather than escape
the gate. It does not substitute an empty/not-found value.

### 2. hardcoded-config-values

**legitimate-variant** — `tests/conftest.py:89` uses a literal two-second
daemon-thread join timeout. The cue matched (numeric literal in an API call),
but it is a teardown ceiling more than 80 times the documented 25 ms sampler
cadence; failure to join cannot block process exit. External-tool timeouts,
memory budget, chunk sizes, sector sizes, and format offsets are otherwise
named module constants that fail loudly or are protocol constants.

### 3. missing-network-timeout

**no candidates** — scanned every `subprocess.run` and
`urllib.request.urlopen` call. Runtime and seedtools pass named timeouts, and
`tests/test_tooling_hardening.py:15-32` AST-enforces that invariant.

### 4. narrating-comments

**false-positive-shape** — numbered comments in
`seedtools/make_cso_fixture.py:61-81`,
`seedtools/make_ps1_bincue_fixture.py:301-313`, and
`seedtools/make_saturn_dc_raw_fixture.py:283-295`, plus the check banners in
`substratum/verify.py:82-110`, match step/banner cues. They separate genuinely
different proof phases (author, structural anchor, independent extraction,
manifest) and mirror the frozen four-check protocol, which the checklist
explicitly permits.

### 5. near-identical-siblings

**false-positive-shape** — `substratum/formats/ps1_bincue.py` and
`substratum/formats/saturn_dc_raw.py` share raw-sector remapping structure,
but differ materially in CUE ownership, Mode-2 XA subheaders, mixed
2048/2324-byte payload semantics, and the public sector API. A shared base
would obscure the format-specific refusal rules rather than substantially
shorten the implementations.

### 6. convention-drift

**no candidates** — checked sibling normalizer names, one-layer return
shapes, imports, sniff/normalize pairs, and manifest construction. Runtime
modules consistently expose `sniff` plus `normalize_<format>` and return the
frozen `ByteView | FileTree` shapes.

### 7. inconsistent-error-handling

**legitimate-variant** — CHD discovery at
`substratum/formats/chd.py:61-94` raises `FileNotFoundError` for an absent
external executable, whereas malformed media normalizers raise `ValueError`.
The cue matched sibling-wrapper asymmetry, but these are different failure
classes; tests enforce the executable-discovery contract and the public
normalization dispatcher otherwise lets typed failures propagate uniformly.

### 8. mutable-default-arguments

**no candidates** — AST/regex scan found no `=[]`, `={}`, `=set()`,
`=dict()`, or `=list()` function defaults.

### 9. assert-for-runtime-validation

**false-positive-shape** — module-level layout identities at
`substratum/formats/ps1_bincue.py:75` and
`substratum/formats/saturn_dc_raw.py:50` check developer-authored protocol
constants, not external data. The cache assertion at
`substratum/formats/ps1_bincue.py:269` is type narrowing after the cache-key
branch; the preceding state transition guarantees the value independently.
No external file or caller input relies on an `assert`.

### 10. async-await-mismatch

**not applicable** — the project has no async functions, promises, event
loop, or coroutine subsystem.

### 11. brittle-error-detection

**no candidates** — no production control flow branches on exception text.
Tests use `pytest.raises(..., match=...)` to verify stable refusal messages;
they do not steer runtime behavior.

### 12. f-string-in-logger-call

**not applicable** — runtime and seedtools do not use the stdlib logging
module or logger calls.

### 13. print-instead-of-logging

**false-positive-shape** — `print()` calls are confined to executable
seedtools with `if __name__ == "__main__"` entry points, for operator-facing
CLI results. Runtime library modules do not print.

### 14. resource-leak-no-context-manager

**false-positive-shape** — `substratum/formats/chd.py:119-163` uses
`NamedTemporaryFile(delete=False)` and `mkdtemp`, matching both cues, because
chdman needs named paths and the decoded file must outlive the normalize
call. Every failure path deletes its owned files, and successful ownership
passes to `_TempFileSource`, which supplies idempotent `close()`, context
management, and a `weakref.finalize` fallback.

### 15. shell-true-subprocess-injection

**no candidates** — scanned all subprocess and OS process calls; commands
use argument arrays and none uses `shell=True`, `os.system`, or `os.popen`.

### 16. sleep-based-synchronization

**false-positive-shape** — `tests/conftest.py:81` sleeps in the daemon RSS
sampler. The delay is the sampler's deliberate 25 ms cadence, not a guess
that another operation has completed.

### 17. string-built-sql

**not applicable** — no SQL, database client, cursor, or query construction
exists in the audited code.

### 18. swapped-args

**false-positive-shape** — positional `FileEntry`/`FileTree` construction in
synthetic seedtools and gate self-tests matches the multiple-compatible-
argument cue. Cross-checking the calls against the dataclass field order
found no swapped paths, kinds, offsets, sizes, sources, formats, or entries;
production parsers predominantly use keywords at the riskier construction
sites.

### 19. tarfile-extractall-without-filter

**no candidates** — there is no `extractall`. The only stdlib archive reader,
`seedtools/vendor_tools.py:162-168`, reads a cryptographically pinned ZIP and
writes only allow-listed `bin/wit.exe` and DLL basenames into a fixed
directory.

### 20. unjustified-lazy-import

**real-defect** — imports inside test functions have no circular, optional,
or startup-cost justification:

- `tests/test_gate.py:83,100,114` imports `FileSource` three times.
- `tests/test_ps1_bincue.py:391-392` re-imports types/functions already
  imported at module scope.
- `tests/test_saturn_dc_raw.py:204` re-imports `normalize_iso9660`, already
  imported at module scope.
- `tests/test_gc_fst.py:217,233,235` locally imports stdlib modules and a
  seedtool without a deferred-dependency reason.

The cue matched exactly: function-body imports, including repeated imports
and stdlib imports, without a lazy-form comment. This is maintainability
debt in the shipped conformance gate, not a runtime correctness fault.

### 21. unreachable-defensive-guard

**no candidates** — inspected guard clusters in public `read_at`, `sniff`,
normalizer, CUE, and archive-entry paths. They validate paths, file bytes,
offsets, or other serialization-boundary data; no internal-only helper guard
was contradicted by all callers.

### 22. weak-test-assertion

**real-defect** — format-specific refusal tests often mutate one exact field
but assert only that *some* `structural:` problem occurred. The cue matched:
the test name promises a specific behavior while the assertion is generic,
so an unrelated early parser failure would keep the test green.

- `tests/test_iso9660.py:81,88`
- `tests/test_gc_fst.py:118,164,308,330`
- `tests/test_chd.py:199`
- `tests/test_cso.py:154,163,172,180,188,198,213`
- `tests/test_ps1_bincue.py:235,246,354,362,371`
- `tests/test_saturn_dc_raw.py:154,165,174,184`
- `tests/test_wii_u8_arc.py:90,118`
- `tests/test_xdvdfs.py:123`

The generic category assertions in the gate self-tests and wrong-slicer
mutants were not included: those tests explicitly promise only the gate
stage or that the mutant dies, so their assertions match their stated
contract.

### 23. off-by-one

**false-positive-shape** — the
`range(0, len(table) - 14, 0x10)` scans at
`tests/test_xdvdfs.py:149,177,197,226` matched the boundary cue. XDVDFS
records are 16-byte aligned; for the 0x800-byte tables the range includes
the final aligned header start (0x7f0), and each variable-length name is
separately bounds-checked. No boundary is skipped.

### 24. wrong-tool-for-job

**real-defect** — three hot paths use single-item primitives for bulk work:

- `substratum/verify.py:59-61` compares every byte in Python even when two
  entire 1 MiB chunks are equal. A bulk `bytes` equality check can skip the
  byte search for the overwhelmingly common equal case.
- `substratum/formats/ps1_bincue.py:303-309,393-397` reads one raw sector per
  call during both cooked reads and eager validation. With `FileSource`, each
  call reopens the carrier.
- `substratum/formats/saturn_dc_raw.py:110-116,159-168` has the analogous
  sector-at-a-time read pattern.

The checklist cue is “bulk operations using single-item primitives in a
loop.” The consequence is measured, not hypothetical: on this host at
`392e1da`, normalizing the 157,246-sector BursTrick carrier took 6.181793 s,
and `_first_diff` over one equal 110,608,384-byte reference took 4.104896 s;
the complete local gate took 185.63 s.

## Compound finding

The entry-24 verifier loop and raw-sector loops compound on retail PS1
fidelity checks: each 1 MiB verifier chunk triggers hundreds of sector reads
that each reopen the BIN, then the equal output is compared byte by byte in
Python. Fixing either layer leaves the other cost intact, so both should be
benchmarked and hardened as one bounded streaming-performance unit.

## Uncategorized observations

No additional correctness or security issue fell outside the taxonomy.
The optional ISO9660 retail pressing and Saturn/Dreamcast homebrew anchors
remain proof-strengthening opportunities, not defects in the current green
normalizers.

## Suggested fix order

1. Strengthen the format-specific structural-red assertions to require the
   expected refusal reason, so unrelated parser failures cannot satisfy them.
2. Batch raw-sector validation/remapping and use bulk equality before
   locating a differing byte; preserve bounded memory and exact first-diff
   semantics, then compare focused and full-suite timings.
3. Hoist the unjustified test imports to module scope.
