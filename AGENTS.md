# Working on Substratum

1. **Read `DESIGN.md`** (frozen), then take a READY row from
   `NORMALIZERS.md`. One session = one normalizer (or one explicitly-
   scoped prep row). A row whose deps aren't vendored or whose fixture
   plan isn't satisfiable is not dispatchable.
2. **NEVER read `F:\game`.** Fixtures come only via the three tiers in
   DESIGN § 5 (synthetic / homebrew / Kenrin-fulfilled FIXTURE REQUEST
   drops in `fixtures/_local/`). Retail bytes never enter git; published
   artifacts are metadata only.
3. **The gate is `uv run pytest`** via `substratum.verify.run_checks` —
   all four checks. **Author each expected manifest independently of your
   parser** (derive it from the differential tool's listing + the format
   spec); a manifest generated by the code under test is a one-party
   round-trip and is forbidden. Reference bytes for fidelity come from
   the independent tool's extraction, never from your own `tree.read`.
   Check 4 diffs a deterministic 16-file sample per fixture (DESIGN § 3);
   `SUBSTRATUM_FULL_FIDELITY=1` opts one run into diffing every file
   instead. That flag is additive — it never relaxes the default, so a
   green under it implies a green without it.
4. **Contract discipline:** `substratum/contract.py`, the schema, and
   `verify.py` are frozen program-wide (four downstream segments bind to
   them). A normalizer returns exactly ONE layer — a CHD gives a
   `ByteView`; never recurse into inner filesystems (the caller
   composes). Structural-only green does not exist: no differential tool
   → self-consistency proof or the unit stays out of the backlog.
5. **Tool pinning:** record the exact differential-tool version in the
   NORMALIZERS.md row AND in the manifest's `tool_versions` — a re-run on
   a drifted binary must fail loudly.
6. **This repo lives on Windows** (Python 3.13 + uv + scoop 7-Zip on
   PATH). Keep everything byte-exact: `.gitattributes` disables eol
   conversion — do not "fix" it; fixtures are binary truth.
