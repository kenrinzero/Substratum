## Findings by entry

### 1. swallowed-exceptions

**legitimate-variant (repeat)** — `substratum/verify.py:88` still catches
`Exception` (`# noqa: BLE001`) and returns the frozen four-check gate's
structural-red diagnostic. The cue matches, but this is the documented
normalization trust boundary: every parse failure must become a structural
result rather than escape the gate, and it does not substitute an empty /
not-found value.

### 2. hardcoded-config-values

**legitimate-variant (repeat)** — `tests/conftest.py:89` retains its literal
two-second daemon-thread join ceiling. The numeric-literal-in-an-API-call cue
matches, but the ceiling is over 80× the documented 25 ms sampler cadence and
cannot block process exit. Runtime/seedtool timeouts (ctrtool's 300 s,
seedtool `TOOL_TIMEOUT_SECONDS`, vendor `DOWNLOAD_TIMEOUT_SECONDS`), batch
sizes (512 raw sectors, 256-window CTR blocks, 4-entry LRU caps), AES block
size, and NCCH/region offsets are otherwise named module constants or protocol
constants.

### 3. missing-network-timeout

**no candidates** — every `subprocess.run` in runtime (`three_ds_ncch_enc.py`,
`three_ds_ncch_enc_seed.py`, `chd.py`) and the new seedtools
(`stage_3ds_ncch_enc_*.py`, `stage_wii_*.py`) carries a timeout (the seedtools
share `vendor_tools.TOOL_TIMEOUT_SECONDS`; runtime uses its own
`_CTRTOOL_TIMEOUT_SECONDS`). Every `urllib.request.urlopen` in `vendor_tools.py`
carries `DOWNLOAD_TIMEOUT_SECONDS`. `tests/test_tooling_hardening.py:15-32`
still AST-enforces the runtime invariant.

### 4. narrating-comments

**false-positive-shape (repeat)** — the new modules carry dense provenance
comments (the two-key NCCH model in `three_ds_ncch_enc_96.py:18-55`, the
FIPS-197 section cites in `_aes.py`, the key-discipline blocks in
`wii_partition.py` / `three_ds_ncch_enc_seed.py`). These explain non-obvious
constraints (3DS crypto hierarchy, counter geometry, Wii word-offset finding)
and mirror the frozen four-check protocol banners in `verify.py:82-110`, which
the checklist permits as phase-boundary / algorithm-explanation comments. No
comment restates the line beneath it in prose.

### 5. near-identical-siblings

**false-positive-shape (repeat)** — the three `_TempFileSource` wrappers
(`chd.py`, `three_ds_ncch_enc.py`, `three_ds_ncch_enc_seed.py`) and the two
lazy decrypt sources (`_DecryptedNcchSource`, `_DecryptedPartitionSource`)
share a skeleton, but the checklist's threshold is three-or-more *sequential*
blocks differing only in an identifier, or near-identical *method bodies*. The
`_TempFileSource` triple is a 20-line idempotent-cleanup + finalizer wrapper
intentionally duplicated so each decode layer is independently dispatchable
(the design rule stated in each module's header). The two decrypt sources
differ materially: Wii is AES-CBC over fixed 0x7C00 clusters keyed by a
per-cluster IV; 3DS 9.6 is AES-CTR over variable encrypted sub-spans with a
mid-stream key switch and region-relative counter indexing. A shared base
would obscure both formats' refusal/geometry rules. No real sibling collapse
is available.

### 6. convention-drift

**no candidates (resolved repeat)** — re-verified the prior cross-normalizer
path-component fix at the new head. `iso9660.py`, `gc_fst.py`, and
`wii_u8_arc.py` still reject `.`, `..`, `/`, `\`; and the **new** Wii
filesystem normalizer `wii_fst.py:94` applies the identical guard
(`name in {".", ".."} or "/" in name or "\\" in name`). Sibling normalizer
naming, one-layer return shapes (`ByteView` vs `FileTree`), sniff/normalize
pairs, and manifest construction are consistent across the registry
(`normalize.py:77-107`).

### 7. inconsistent-error-handling

**legitimate-variant (repeat)** — CHD / ctrtool executable discovery
(`chd.py`, `three_ds_ncch_enc.py:_ctrtool_exe`,
`three_ds_ncch_enc_seed.py:_ctrtool_exe`,
`three_ds_ncch_enc_96.py:_load_keyx`) raises `FileNotFoundError` for a missing
external artifact, whereas malformed media raises `ValueError`. The
sibling-wrapper cue matches, but missing operator machinery (chdman / ctrtool
/ keyset / seeddb / common key) and malformed on-media input are genuinely
distinct failure classes; the public normalizer dispatcher otherwise lets
typed failures propagate uniformly.

### 8. mutable-default-arguments

### 11. brittle-error-detection

**legitimate-variant (repeat)** — `three_ds_ncch_enc_seed.py:_field` (line 230)

header reconstruction, and `normalize_3ds_ncch_enc_seed` (line 372) gates the
7.x-seed scope on the literal `"Secure (1)"` substring. The string-based

### 13. print-instead-of-logging

### 14. resource-leak-no-context-manager

**false-positive-shape (repeat)** — the `NamedTemporaryFile(delete=False)` +
`mkdtemp` sites in `three_ds_ncch_enc.py:222,293` and
`three_ds_ncch_enc_seed.py:365,392` stage paths for ctrtool (which requires
filenames) and assemble a decoded NCCH that must outlive the normalize call.
Every failure path deletes its owned files (`except BaseException:
shutil.rmtree(...)`; `finally: unlink(...)`), and successful ownership passes
to a `_TempFileSource` with idempotent `close()`, context management, and a
`weakref.finalize` fallback. The lazy decrypt sources' caches are cleared on
`close()`. No handle leaks.

### 20. unjustified-lazy-import

**real-defect (NEW, repeat-of-class)** — `import struct` appears inside three
function bodies of `substratum/formats/three_ds_ncch_enc_seed.py` and is **not**
imported at module scope:

- line 163, inside `_is_cia()`
- line 175, inside `_content_offset()`
- line 290, inside `_assemble_nocrypto_ncch()`

Confirmed via AST (`ast.walk` over every module in `substratum/`): these are
the only function-local imports in the runtime, and `struct` is a stdlib module
with no circular, optional-dependency, or heavy-startup justification — the
same defect class the `2026-07-26` memo resolved for test files in `52f9b55`,
now re-introduced in runtime code. The module already uses
`struct.unpack_from` / `struct.pack_into` heavily; the three function-local
imports are pure cargo. Maintainability debt, not a runtime correctness fault.

### 21. unreachable-defensive-guard

### 23. off-by-one

**false-positive-shape (repeat)** — the counter-block indexing in
`three_ds_ncch_enc_96.py:398` (`blk = (pos - region_base) // _AES_BLOCK`) and
the `_first_diff` windowing in `verify.py:60-66` match the boundary cue. Both
are correct: CTR block indices are region-relative (ExeFS sub-spans share one
continuous stream per the two-key model), and `_first_diff`'s
`range(chunk_size)` runs over an already-known-differing chunk. The
`range(0, len(table) - 14, 0x10)` XDVDFS scans from the prior memo are
unchanged and still include the final aligned header. No boundary is skipped.

### 24. wrong-tool-for-job

**no candidates (resolved repeat)** — the prior three hot loops (verifier
byte-wise scan, PS1/Saturn sector-at-a-time reads) remain fixed at the new head
(`verify.py:60` bulk-equality short-circuit; PS1/Saturn 512-sector batching).
The new 3DS/Wii code avoids the defect: `_DecryptedNcchSource` decrypts in
bounded 256-block CTR windows (not block-at-a-time), and the lazy CBC/CTR
decrypt paths cache payloads rather than re-decrypting per read. The
NIST-vector anchor for `_aes.py` is the right tool (public reference vectors,
not a fixture round-trip). The remaining single-item loops operate on small
authoring fixtures or are the format algorithm itself.

## Uncategorized observations

1. **`three_ds_ncch_enc_seed.py:_assemble_nocrypto_ncch` logo-absence flow is
   fragile but gated.** When the ctrtool report omits "Logo offset" the `try`
   at line 311-320 sets `logo_off = logo_size = 0`, but the later `place("logo",
   logo_off)` (line 344) is guarded by `if logo_off and logo_size`, so a logo
   region is not placed. This is correct behavior, but the `logo_off`/`logo_size`
   names are bound inside the `except ValueError` in a way that relies on the
   `try` failing *before* assignment; it works only because `_hex_field` raises
   on the missing "Logo offset" label before either name is set. No defect —
   flagged only as readability debt worth a comment if the region-reconstruction
   logic is touched again.

2. **Key-discipline is sound and consistent.** The new keyed work (Wii common
   key, 3DS keyset, seeddb) correctly keeps all key material in
   `fixtures/_local/` (verified gitignored: `git check-ignore` reports
   `fixtures/_local/aes_keys.txt` ignored), reads only presence/length (never
   contents/hashes) in code, and the committed `test_keyset.txt` uses
   deliberately-generated test values documented as publishable. No retail key
   bytes or decrypted retail payloads enter git.

3. **Documentation is accurate at the audited head.** README status (v0.0.18,
   seventeen green normalizers, the two-key model, the pure-Python 9.6 path,
   Wii chain, path-traversal refusals), `docs/3DS-PURE-PYTHON-AES-CTR-PLAN.md`
   (C1 pinning, ROL-87 correction, two-key finding), and
   `docs/3DS-KEYED-WORK.md` / `docs/WII-KEYED-WORK.md` (crypto hierarchy, key
   discipline) all match the code and commit history. The plan's "Open items"
   correctly record C1 and the counter as pinned/resolved. No stale-status
   drift comparable to the `2026-07-26-b` GC-FST docstring issue was found.
